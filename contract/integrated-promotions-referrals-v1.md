# Integrated promotions and referrals contract v1

Date: 2026-10-21. Prospective under `brief/project.json` v107. Frontend and Backend must agree this contract before implementation. This contract changes no app code or live service. It follows `research/lovable-promotions-referrals-v1.md`, A4 demo quote/receipt contracts, and A6 published event versions.

## Scope and money rules

Organizer owners manage promo codes for a brand or one of its events. A brand editor may prepare them only if the owner approves activation; a viewer cannot mutate them. The existing event referral setting remains optional and owner controlled. A promotional code reduces the buyer's **ticket** subtotal. A referral code attributes a promoter; it does not reduce the buyer price. At most one promo and one referral code may apply to a quote. No promotion applies to add-ons. No real payment, ticket issue, commission accrual, transfer, or payout occurs in this demo.

Use USD integer cents and integer basis points throughout. For a quote, `originalTicketSubtotalMinor` is the sum of server-stored tier price times quantity. An eligible percent promo calculates `roundHalfUp(originalTicketSubtotalMinor * basisPoints / 10000)`. A fixed promo discounts at most that subtotal. `discountMinor` is clamped to `[0,originalTicketSubtotalMinor]`. `discountedTicketSubtotalMinor=originalTicketSubtotalMinor-discountMinor`. `platformFeeMinor=roundHalfUp(discountedTicketSubtotalMinor*1000/10000)`. `organizerShareBeforeReferralMinor=discountedTicketSubtotalMinor-platformFeeMinor`. If an event has enabled referrals and an eligible code, `referralRewardMinor=min(organizerShareBeforeReferralMinor,roundHalfUp(discountedTicketSubtotalMinor*referralBasisPoints/10000))`. `organizerShareAfterReferralMinor=organizerShareBeforeReferralMinor-referralRewardMinor`. This conservation equation must hold in integer cents. Existing A2 caps referral percent at 90%; never let rewards exceed organizer share. A zero-price result yields zero fee and reward. Processing fees and taxes remain outside these figures until an owner-approved live-payment contract defines them.

Example: one $55.00 ticket, 20% promo, and organizer-set 10% referral yields $44.00 buyer ticket price, $4.40 platform fee, $4.40 illustrative referral reward, and $35.20 organizer share before unassigned processing fees. `amountChargedMinor` remains **0** in demo checkout. Display the original and discounted price, rather than saying the buyer paid $44.00.

## Storage and permissions

A new migration adds `organizer_promotions` with stable UUID, organizer UUID, optional event UUID constrained to that organizer, uppercase normalized code and unique `(organizer_id,code)`, type `percentage|fixed`, `basis_points` or `amount_minor` as an exclusive pair, optional minimum original ticket subtotal, optional maximum real redemptions, active flag, optional expiration, created/updated timestamps, and optimistic version. No buyer-facing description is required. Existing published event referral `enabled`/`percentageBasisPoints` remains the authoritative rate; any rate change uses the A6 owner-approved event revision. A separate `organizer_referral_codes` table records brand/event scoped opaque codes and an optional promoter subject only after a verified customer identity design; demo codes may be owner-created anonymous attribution examples, with no name/email or earnings balance. Never expose all active promo/referral codes through public list endpoints.

Private organizer routes are under `/api/v1/organizers/{organizerId}/promotions`: GET list with bounded pagination; POST create; PATCH `{promotionId}` for changes or activation; DELETE means deactivate, preserving any historical quote reference. Same-origin JSON, Clerk-derived subject, current active membership, owner-only activation, optimistic `expectedVersion` and idempotency key on writes. Foreign brand IDs return 404. Validation rejects blank/oversized/non-ASCII ambiguous codes, invalid percent, negative fixed amount, min greater than supported quote maximum, and expiration in the past. The UI shows code, type/value, scope, minimum, expiry, usage limit, active state, and an edit/review step. It never shows a claimed sales count from demo checkouts.

Private referral-code management is under `/api/v1/organizers/{organizerId}/published-events/{eventId}/referral-codes` with the same owner gate and bounded list/create/deactivate operations. Public detail may say referrals are available and show the organizer's percentage, but does not enumerate codes. A sharer can copy `/events/{eventId}?ref={code}` only for a code they hold. Public code lookup reveals at most valid/invalid status, never the promoter identity. A signed-in promoter account, self-referral policy, actual earning ledger, post-event settlement, cancellation, disputes, tax handling, and payout provider require a separate prospective contract before real rewards are promised.

## Buyer contract and server calculation

Extend the A4 quote POST input with optional `promoCode:string|null` and `referralCode:string|null`, bounded in length, included in canonical idempotency hash. This is an explicit versioned change to the A4 exact-key request contract; migrate its caller and route together. The browser sends selections and codes only, never price, discount, fee, share, or reward. The server resolves code scope, active state, expiration, minimum original ticket subtotal, and event rate inside the quote transaction, locking rows as needed. Return `PROMO_INVALID`, `PROMO_EXPIRED`, `PROMO_NOT_APPLICABLE`, or `REFERRAL_INVALID` with safe copy and field path. Do not distinguish other-brand existence. The quote response adds a `pricing` object containing original subtotal, promo code display, discount, discounted subtotal, platform fee, organizer shares, referral reward, and currency. Keep existing A4 money fields for a coordinated migration only, with `ticketSubtotalMinor` explicitly defined as **discounted** once cut over. A4 receipt stores the complete server-priced quote snapshot and `amountChargedMinor:0`, `demo:true`, `admissionValid:false`, `referralPayoutConnected:false`.

Quotes expire in 15 minutes and hold no ticket, seat, promo use, or referral reward. On demo checkout, recheck event version and promo/referral validity before copying the quote. If a code changed, expired, or reached a limit, return `QUOTE_CHANGED` and request a fresh quote. Same-key successful replay returns the historical receipt before these checks. A6 event revision invalidates stale quotes. No code may cause a quote to change after it has been issued; the new response is a new quote. Demo confirmations are immutable illustrations and **do not increment** promo uses or affiliate metrics. A later real checkout must reserve a promo redemption atomically only after verified payment, with idempotent reversal rules for voids/refunds; that design is outside this contract.

The buyer page places a simple promo entry and optional referral attribution near the ticket price, then updates the server quote. It labels the split as an organizer estimate, not money paid or owed. It must show the $0 demo checkout and no-admission notice at quote and confirmation. Invalid codes stay editable; clearing either produces a new quote. On mobile, the final discounted ticket price is visible before the checkout action. There is no forced signup for demo buyers.

## Gate, tests, and open decisions

`PROMOTIONS_DEMO_ENABLED=false` and `REFERRALS_DEMO_ENABLED=false` by default. Public activation waits for connected Clerk/Neon, applied migrations, owner authorization checks, browser quote/checkout/receipt verification, and confirmation that creator/event revision routes use the same price rules. Disabled routes return a service-unavailable capability response and UI hides the controls. No live provider credential is required for this zero-charge demo.

Required tests cover mixed tiers and seats, percent/fixed promo boundaries, min and max constraints, code scope/expiration/deactivation, case normalization and conflicting codes, 1-cent rounding, 100% discount, referral cap, event revision, repeat idempotency, concurrent quote/checkout, foreign brand permissions, no demo redemption increment, and no PII/payment/ticket issuance. Run real migration-backed tests and a mobile browser flow before enablement.

Decisions for PM before real-money implementation: whether add-ons can be discounted, processing-fee allocation, whether discounts may stack, exact referral promoter identity and self-referral rules, payment processor and refund/chargeback lifecycle, and payout method. For this demo, assume one promo plus one referral, ticket-only discounts, and no monetary earning. These assumptions are explicit so Frontend and Backend can agree without inventing a payment policy.
