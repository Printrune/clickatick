# Creator-to-Neon cutover contract v1

Date: 2026-10-21. Source: `brief/project.json` v104, `backend/legacy-publishing-cutover-v1.md`, approved A1/A2/A4 contracts. **Prospective proposal for Frontend review; no code or service changed.** This supersedes the old creator publication interface only after Frontend/Backend agreement and connected verification. `/creator` voice and text conversation, local draft, visual scene and review remain. New marketplace events require Clerk sign-in, brand ownership and owner review before Neon publication. Payment, admission, email delivery and referral payout remain unavailable.

## User journey and state ownership

1. The visitor speaks or types in `/creator`. The browser maintains `ticketnest-draft` with the existing validated legacy draft, conversation state, scene/media and any failed answer. `/api/chat` and `/api/speech` retain their existing AI/speech capability and error behavior. No Clerk session is required to converse or review locally.
2. The final creator action is **“Save to brand draft”**. Local review remains available. The action does not publish, create an admission ticket or send draft content to a URL. It sets only the existing `clickatick-import-creator=1` session marker, then navigates to `/dashboard?source=creator`. Remove the direct `Publish demo listing` action and obsolete email/local login dialog after the handoff passes. `clickatick-publish-intent-*` is no longer created by new clients.
3. `/dashboard` calls `GET /api/v1/me`. A 401 displays sign-in; `/sign-in` uses Clerk Google/email and a fixed safe return to `/dashboard`. A 503 shows unavailable state and keeps the browser draft. The old `ticketnest-session` cookie is ignored; it is not transformed into a Clerk account and cannot authorize Neon writes. If zero brands exist, the visitor creates one; otherwise they choose a brand explicitly, even when only one is present. Brand creation/selection then navigates to `/dashboard/{organizerId}/events/new?source=creator`. Cancel or back returns to `/creator` with the local record intact.
4. `OwnerDraftEditor` reads the **unchanged** source record from the device and calls the existing brand-scoped import endpoint. A successful import returns a private draft and field-specific warnings; it does not clear the local record or claim local photos transferred. The editor opens `/dashboard/{organizerId}/events/{eventId}`, shows missing address/pin/photo/ticket/disclaimer details, and saves further changes using A2 PATCH. Only the brand owner can import and publish under the currently implemented rights; any later editor capability must follow the agreed staff contract.
5. The owner reviews the saved draft and calls A4 publication. Only a successful A4 response creates `/events/{id}`. Buyers there can use the zero-charge A4 demo quote/checkout, never a real purchase. Failed sign-in, import, photo upload, validation, publish, or navigation leaves the device draft and previously saved private draft available for retry.

The source of truth is browser storage **before import**, Neon `organizer_event_drafts` **after import**, and Neon `public_events` **after owner publication**. The device copy is retained until the organizer explicitly discards it. Blob legacy listings and receipts remain a separate historical system; no implicit ID or owner mapping is inferred.

## Exact active API contract

All A1/A2/A4 JSON endpoints use `{data:<shape>,error:null}` on success and `{data:null,error:{code,message,fields?,currentVersion?,publicUrl?}}` on error. No draft, image data or creator token is placed in the query string. Same-origin checks apply to mutations. Private endpoints derive the Clerk subject on the server and verify active brand membership; brand IDs and draft IDs alone grant no access.

| Step | Request | Response and transition |
| --- | --- | --- |
| Auth/brand list | `GET /api/v1/me` | 200 `{data:{userId,brands:[{id,slug,name,role,permissions,dashboardUrl}],nextAction},error:null}` under A1; 401 `SIGN_IN_REQUIRED`, 503 `AUTH_UNAVAILABLE` or `DATABASE_UNAVAILABLE`. Only active memberships appear. The browser never uses `/api/auth`. |
| Brand creation, when chosen | `POST /api/v1/organizers` with `{name,slug,idempotencyKey:UUID}` | A1 201, same-key replay, or A1 field/conflict errors. Stable key retained across an unchanged retry. |
| Creator import | `POST /api/v1/organizers/{org}/events/import-draft` with `{sourceDraft:LegacyClickatickDraft,idempotencyKey:UUID}` ≤2 MiB | A2 201 `{data:{event:OwnerDraft,warnings:[{path,code,message,localMediaSlot?}]},error:null}`. Same key/body replays same private event. Changed source draft gets a new key. 401/403/404/409/413/422/503 leave the local source intact. No `publicUrl`. |
| Private edit | `GET/PATCH /api/v1/organizers/{org}/events/{eventId}` | A2 `OwnerDraft`, versioned PATCH `{expectedVersion,changes}` and warnings. Changed address clears its prior pin; photos attach only through an approved, ready private asset ID. |
| Owner publication | `POST /api/v1/organizers/{org}/events/{draftId}/publish` with `{expectedVersion:integer,idempotencyKey:UUID}` ≤8 KiB | A4 201 `{data:{event:{id,status:'published',version,sourceDraftId,publishedAt},publicUrl:'/events/{id}',warnings:[]},error:null}`. Identical key/body replay resolves uncertain responses. Required photo/address/pin, future date, inventory, tier, ticket format, reviewed disclaimer and refund policy are validated server-side. Denied/incomplete/disabled states never generate a public URL. |
| Public detail and buyer demo | `GET /api/v1/events/{id}` and A4 quote/checkout/receipt routes | Only tested Neon public events; zero amount charged, no seat hold, sale, admission or buyer PII. |

Import-specific error behavior is inherited from A2. Client validation is advisory; the server validates the full source draft, canonical mapping, brand ownership and media references. A warning such as `LOCAL_IMAGE_UPLOAD_NEEDED` keeps the private draft incomplete and the original data URL on the device. A creator may resume another brand selection without silently copying the draft to a different brand. The browser keeps a stable import key for the same selected brand and canonical source record through network retries; a changed draft or chosen brand gets a new key.

## Legacy routes and rollout responses

At cutover, `POST /api/demo/listings` stops accepting **new** anonymous Blob listings. Proposed exact response: HTTP 410 `{data:null,error:{code:'LEGACY_PUBLISHING_CLOSED',message:'Save this draft to a brand to publish it after review.'}}`, `Cache-Control:no-store`, with no write and no creator cookie. The old client is removed in the same release, so old publish-intent retries receive 410 and the local draft remains recoverable. The old Blob `GET /listing/{id}`, `GET /receipt/{id}`, associated demo checkout/artwork reads and creator-token-based historical marketing behavior remain subject to their existing gates; closure of one write route does not delete stored objects or revoke historical links. If exact replay of a pre-cutover published request is required, it needs a separately agreed read-only lookup without creating new objects. This v1 proposes uniform 410 to minimize ambiguity and write risk.

`POST /api/listings` (Supabase/local legacy) likewise returns 410 once the creator has no caller; `/api/auth` no longer starts OTP or local sessions. A retired auth endpoint must never sign out a Clerk session. `PUBLISHING_ENABLED`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `lib/services.js` `database()/session()`, local PGlite publishing and Supabase `published_events` fallback can then be removed. Preserve `sameOrigin` as a neutral utility for chat/speech/demo/marketing and preserve AI/speech capability projection. Keep `eventPublicationErrors` while `lib/demo-validation.mjs` imports it; delete only obsolete `eventPublicationPath`, `publishedEventPath` and `publicationPayload` after their last callers are gone. Historical SQL/docs are archived evidence, never Neon migrations.

## Public catalog and URL boundary

`/` and `/discover` show the Neon `GET /api/v1/events?cursor=&limit=` catalog as the **single canonical catalog** only after connected A4 public detail, media and buyer-demo verification. The current `NewDemoCatalog` duplicate section and `NEXT_PUBLIC_NEON_DEMO_CATALOG_ENABLED` dual-display behavior are removed in that release. New cards link exclusively to `/events/{id}`. Legacy `/listing/{id}` and `/receipt/{id}` remain direct-link-readable with their existing demo disclosure; the proposed default is to omit them from new search/catalog results. No redirect from a legacy UUID to Neon occurs without an explicit migration map. Catalog outage shows a real error state rather than an empty-events claim. Pagination is server-cursor-based; client search/filter only covers fetched rows unless a separate search API is agreed, so the UI must not imply it searched all events.

The canonical-catalog switch and legacy write closure are one rollout unit, not separate toggles that allow an invisible anonymous Blob write. A server-side cutover gate defaults off and may turn on only after connected Clerk/Neon/private media, old-link, and buyer-demo browser checks. Frontend and Backend must agree the flag name and deployment order before code. Until then, the existing Blob public catalog and creator behavior remain as they are; this document does not claim a live cutover.

Backend owns closure of the two old write paths, neutral helper extraction, preservation of Blob read routes, removal of Supabase runtime and exact 410 response, plus tests. Both agree API/error shapes and flag ordering in a PM handoff before editing shared files.

Required automated checks: creator voice/text/local restore unaffected; no `/api/demo/listings` or `/api/listings` POST from new UI; 410 routes never write even with old credentials/intent; old `/listing` and `/receipt` direct reads survive; Clerk 401/503 retains draft; two-brand choice; idempotent import replay and changed-draft key; local image warning and later attachment; owner-only A4 publish/invalid photo+pin rejection; old Supabase env vars cannot re-enable publication; chat/speech/marketing origin tests after `sameOrigin` extraction; Neon catalog pagination and outage states; zero-charge receipt. Browser checks cover phone/desktop, canceled sign-in, lost network response, and old direct links. No external service success is claimed from fixture tests.
