# Integrated Phase A6 — seat authoring and published revisions, prospective API contract v1

Date: 2026-10-21. Source of truth: `brief/project.json` v104, `integration/design/integrated-phase-a6-v1.md`, `frontend/integrated-phase-a6-proposal-v1.md`, and A2/A4/A5 contracts. **Proposal for Frontend agreement before implementation.** No A6 migration, API, deployment or payment connection exists by virtue of this document.

## Invariants and ownership

`public_events.id` and `/events/{id}` remain stable through approved edits and a brand rename. The A2 source draft stays locked. An active editor or owner may prepare a private revision; only an active brand owner may approve, return or cancel. Every public change, including spelling, requires owner approval in A6. Exactly one open revision per event (`draft|returned|pending_review`); a second author edits that same working copy using optimistic concurrency. Approval creates an immutable numbered public version and atomically switches the active pointer. Rejected/returned changes never affect the public page. Cancellation blocks approval and new quotes/checkouts; existing versions and no-PII receipts remain readable until a separately authorized event deletion flow. No demo seat becomes sold, held or reserved.

The canonical proposed content is a full A2 `EventDraftInput` snapshot, not a partial patch against a moving public event. A revision copies the currently approved snapshot on creation. The backend owns validation, version/seat IDs, diff classification, approvals, quote and receipt consistency. The frontend owns keyboard-accessible seat authoring, comparison, conflict recovery and accurate demo copy. A5 storefront event links retain the same event UUID; its grid reads the active approved version only.

## Migration 007 and versioned storage

Backfill each existing A4 event as version 1 from `public_events.snapshot`, preserving its historical publish timestamp. Add `public_events.active_version INTEGER NOT NULL DEFAULT 1` with `(id,active_version)` FK to version rows after backfill. Existing `public_events.version` is the **event status/concurrency version** (including cancellation), not the approved content version; never conflate it with `active_version`. Keep `public_events.snapshot` as a transactionally updated compatibility projection until all A4 readers use the active version. Backfill and pointer swap must be transactional; absent/malformed v1 snapshots fail migration or return 503, never silently construct a new event.

Add `public_event_revisions(id UUID PK,event_id UUID,organizer_id UUID,base_public_version INTEGER,revision_version INTEGER > 0,status draft|returned|pending_review|approved|withdrawn,draft JSONB object,created_by_clerk_user_id,updated_by_clerk_user_id,submitted_at,reviewed_at,reviewed_by_clerk_user_id,return_note TEXT,created_at,updated_at)`, FK to event and base version, partial unique `(event_id) WHERE status IN ('draft','returned','pending_review')`. A returned revision becomes editable again; an approved/withdrawn revision cannot be edited. Server audit captures actor/action/version/time without exposing Clerk subjects publicly. Idempotency claims use existing server pattern, scoped by verified subject, brand, event, operation and key; canonical request hash and response identity commit with mutation.

For versioned buyer reads, add immutable version-keyed normalized children or equivalent fully indexed version projections: occurrence, tier, section, seat, pool and media rows have `(event_id,event_version,child_id)` identity and FK to the version, not merely mutable A4 `(event_id,child_id)`. Existing A4 rows become version 1. Approving never updates or deletes older child rows. Public catalog/detail, section seats and new quotes query **one active version** from a single DB snapshot; no response combines an active event with old seats, prices or photos. A3 asset deletion checks references from every retained approved version, every open revision and any receipt snapshot that needs the asset, including cancelled events. A replacement image does not release the older version's asset. Avoid copying Blob bytes between versions.

Existing A4 `demo_quotes.event_version` becomes the approved content version, not the status version; migrate existing rows to 1 when unambiguous. Add `demo_receipts.event_version` and `demo_receipts.event_snapshot JSONB NULL`; new A6 receipts require a validated non-null snapshot, but historical A4 receipts retain null. This schema supports truthful legacy rendering without filling missing history from the latest listing. Do not rewrite existing `response_json` to invent title, venue or time.

## Seat-map document and identity

A6 extends A2 `seating.sections` rather than storing a 10,000-seat JSON list. A section has stable UUID, name, position, `rows` 1–100, `seatsPerRow` 1–100, optional section-wide `seatTierId`, sparse `removedSeats:[{row,number}]`, sparse `accessibleSeats:[{row,number}]`, and `seatOverrides:[{row,number,seatTierId:null|UUID}]`. All coordinates are integer 1-based; every array is unique, sorted canonically by row then number, and coordinates must fall inside geometry. Removed coordinates cannot also be accessible or overridden. A section-wide null means any seated tier; a per-seat null override restores that rule. A tier `seatPolicy:none` can never be a seat assignment. Section names need not be globally unique, but `(section position,row,number)` identifies a visible seat within one version. Reject ambiguous duplicate section positions/labels, malformed overrides and incompatible tier refs with JSON field paths. Existing A2 sections lacking new arrays normalize to empty arrays on read and are backfilled only in a private write, not guessed in public history.

The A2 256 KiB save limit, ≤50 sections and ≤10,000 configured seats remain. Count `rows × seatsPerRow − removedSeats.length`; sparse arrays have a bounded combined maximum of 10,000 coordinates and 256 KiB request. The compact document makes authoring possible without 10,000 DOM nodes; public expansion happens server-side at approval. Public seats retain stable UUIDs **only when the same section UUID and row/number still represent the same physical place**. Rename or accessibility/tier edit does not change a seat ID. Resizing by adding/removing other rows or seats preserves unaffected coordinates. Deleting/recreating a section, moving a seat to another section, changing row/seat numbering, or changing its physical position creates a new seat ID; never reuse an old ID for a different place. Because coordinate equality cannot prove physical equivalence after arbitrary layout rearrangement, any `geometryReset:true` on a section forces new IDs for that section; the review screen must identify this destructive identity change. Visual pan/zoom or CSS layout changes do not. Old version seat labels and IDs stay in old versions and receipts. Server derives display `section · row A · seat 12` from configured names/coordinates and validates generated label uniqueness within a version. Grid-only numbered seats with sparse missing coordinates are in A6; free-form polygons/arena geometry are explicitly deferred, and unsupported fields reject validation rather than disappear.

The authoring UI may page through `GET /api/v1/organizers/{org}/events/{draftId}/seat-map?sectionId=&row=&cursor=&limit=` for draft-derived seats, at most 200, with `configuredOnly:true`; the draft itself remains compact. A published revision uses the same projection at `/api/v1/organizers/{org}/published-events/{eventId}/revisions/{revisionId}/seat-map`. Cursors bind brand, draft/revision version, section and row filter; stale/mismatched cursor returns 409 `SEAT_MAP_CHANGED` or 400 `INVALID_CURSOR`. Returns `{data:{sectionId,seats:[{id:null|UUID,row,number,label,accessible,compatibleTierIds,configuredOnly:true}],nextCursor},error:null}`. Null ID means a not-yet-approved new coordinate; browser selection uses section/row/number until approval. `GET` is member-scoped and does not publish the private map.

Inventory remains independent: `dateScope:per_occurrence|across_dates` selects per-date versus shared configured pools; `tierScope:shared|allocated` selects whether tier allocations sum to total capacity. GA `seatPolicy:none` never requires geometry. `optional|required` tiers need at least one compatible numbered seat; required seating can quote at most the configured compatible distinct seat count per selection, but total event capacity need not equal seat count because GA and optional unassigned places can coexist. A configured section/seat count is never represented as remaining availability. Changing date scope, tier scope, tier IDs, seat policies or geometry revalidates the complete draft at save and approval. No inferred capacity switch is allowed.

## Private revisions and exact API

All routes follow A1–A5 `{data,error}` envelope, bounded JSON, same-origin mutation checks, server-derived Clerk subject, active membership and brand scope. Unknown/foreign event and revision IDs return 404; disabled/insufficient role returns 403. Every private response is `Cache-Control:no-store`. Public version remains unchanged for all actions except owner approval.

`GET /api/v1/organizers/{org}/published-events/{eventId}/revisions/current` returns `{data:{event:{id,status,activeVersion,eventVersion,publicUrl},revision:null|{id,basePublicVersion,version,status,draft,updatedAt,updatedByLabel,submittedAt,reviewedAt,returnNote},permissions:{editRevision,submitRevision,reviewRevision,cancelEvent},changes:[{path,kind:"material",before,after}],validation:{errors:[{path,code,message}],warnings:[{path,code,message}]}},error:null}`. Diff `path` uses A2 field paths. `before` and `after` are bounded structured scalars or arrays, never only localized display strings; media uses asset ID and safe preview URL, no Blob token. Pending revisions are read-only to editors. `updatedByLabel` is a safe role label, not Clerk subject or email. Server returns exact validation on each read; until a finer taxonomy is prospectively agreed, every change has `kind:"material"`.

| Action | Request, limit | Success and state | Conflict/recovery |
| --- | --- | --- | --- |
| `POST .../revisions` | `{basePublicVersion,idempotencyKey}` ≤8 KiB | 201 working copy at revision version 1; if an open revision exists, 409 `REVISION_EXISTS` with safe current-revision URL | `PUBLIC_VERSION_CONFLICT` includes active version; same key/body replays original creation. |
| `PATCH .../revisions/{revisionId}` | `{expectedRevisionVersion,changes:Partial<EventDraftInput>}` ≤256 KiB; A2 top-level replacement/changed-address pin rule | 200 new version plus full revision, diff and validation; canonical no-op keeps version | 409 `REVISION_VERSION_CONFLICT` with current version and refetch URL. Pending/approved/withdrawn is 409 `REVISION_NOT_EDITABLE`. |
| `POST .../revisions/{id}/submit` | `{expectedRevisionVersion,idempotencyKey}` ≤8 KiB | 200 `pending_review`, submitted timestamp; requires complete publish validation and at least one changed field | Field errors 422; version conflict 409. Same key/body replay. |
| `POST .../revisions/{id}/return` | `{expectedRevisionVersion,idempotencyKey,note}` ≤8 KiB; note 1–500 chars | Owner-only 200 `returned`, revision version +1, public unchanged | Pending only; conflict 409; same key/body replay. |
| `POST .../revisions/{id}/approve` | `{expectedRevisionVersion,expectedPublicVersion,idempotencyKey}` ≤8 KiB | Owner-only 200 `{event:{id,status:"published",activeVersion,eventVersion,publicUrl},revision:{id,status:"approved",version},changes:[...]}`; one atomic content-version increment and pointer swap | 409 stale revision/public version with current numbers and refetch URL; 422 validation; `EVENT_CANCELLED` if cancelled. Same key/body replay first. |

The server checks idempotency **before** status/version checks on repeat requests. A repeated key with different canonical body returns 409 `IDEMPOTENCY_CONFLICT`. Approval transaction locks event, revision, membership, referenced media and affected version rows; validates owner, base active version, full publish rules, media readiness, exact seat identity, occurrence/DST, tier/price/capacity and disclaimer; writes immutable version + child rows; switches active pointer and event status version; marks revision approved; commits response identity. A loser of simultaneous approvals receives conflict, not a second public version. A stale draft save never overwrites later edits. Cancellation follows A4 owner route and freezes pending revision as unreadable for approval, but it remains viewable for audit; cancellation does not delete version/media/receipts.

## Public version, quote and receipt contract

`GET /api/v1/events/{id}`, catalog, storefront grid and section-filtered seats keep A4 route shapes, adding `activeVersion` to event detail and optional summary. Reads use only active approved version. A cancelled detail remains readable with status notice. `GET /api/v1/events/{id}/versions/{version}` is **not** a public browsing route in A6; immutable versions are private to active brand members through `GET /api/v1/organizers/{org}/published-events/{id}/versions/{version}` with a bounded owner-safe projection and no customer PII.

New quote response includes `eventVersion` equal to `activeVersion`, and selection stores stable occurrence, tier and seat IDs from that version. `GET` on an old quote returns `state:"event_changed"` and `{code:"EVENT_VERSION_CHANGED",currentEventVersion,detailUrl:"/events/{id}"}` as a recovery hint; it does not remap IDs, price or expiry. `POST /demo-checkouts` with stale quote returns 409 `EVENT_VERSION_CHANGED` before writing a receipt. If the event is cancelled, existing A4 `EVENT_CANCELLED` remains. A committed checkout's idempotent replay still returns its original receipt even after approval/cancellation. A new quote after approval sees the new version only. These rules apply even if a seat ID happens to survive unchanged, because prices, venue or dates may have changed.

For each **new** receipt, store an immutable no-PII `eventSnapshot` with `eventVersion`, event title/type, occurrence ID, local start/UTC instant/timezone and duration, business/event venue names and addresses plus pin coordinates/map link, selected tier IDs/names/prices/quantities, seat IDs/section/row/number/labels/accessibility, subtotal/platform fee/organizer share/`amountChargedMinor:0`, currency, reviewed disclaimer/restrictions/refund-policy text and explicit demo/admission/reservation flags. The projection never includes buyer name, email, payment data or raw private media path. Use versioned media ref IDs if a receipt legitimately displays an image; never replace its image with a new version's image. Receipt `response_json` and `event_snapshot` are written in the checkout transaction from the quote's immutable version, not by a later public event read. `GET /api/v1/demo/receipts/{id}` presents captured facts and a separately fetched current `eventStatus`; cancellation notice is metadata, not mutation of the captured snapshot. A4 legacy receipts with `eventSnapshot:null` show only fields actually present in old `response_json` and `"Some original event details were not recorded for this demo confirmation."`; they may link to the current listing, clearly labeled current information. Never reconstruct old facts from current version. Receipt URLs remain valid until the explicit event deletion flow; no automatic expiry or cancellation deletion.

Media attached to new versions is read by version-keyed same-origin public media routes; old versions/receipts retain references. A3 deletion rejects referenced assets, returning `ASSET_REFERENCED` with a count, until an authorized deletion flow explicitly resolves all historical references. `MEDIA_UNAVAILABLE` is 503 for an asset required by approval; missing optional public media does not alter JSON facts and renders a labeled fallback.

## Error and activation gates

Standard errors: 400 `INVALID_BODY|INVALID_CURSOR`; 401 `AUTH_REQUIRED`; 403 `ROLE_DENIED`; 404 inaccessible IDs; 409 `REVISION_EXISTS|REVISION_NOT_EDITABLE|REVISION_VERSION_CONFLICT|PUBLIC_VERSION_CONFLICT|EVENT_CANCELLED|EVENT_VERSION_CHANGED|SEAT_MAP_CHANGED|IDEMPOTENCY_CONFLICT`; 422 `SEAT_GEOMETRY_INVALID|TIER_COMPATIBILITY_INVALID|INVALID_SELECTION|PHOTO_NEEDED|SCHEDULE_TIME_INVALID|SCHEDULE_TIME_AMBIGUOUS`; 429 bounded abuse limit with `Retry-After`; 503 `DATABASE_UNAVAILABLE|MEDIA_UNAVAILABLE`. Conflict envelope may add `{currentVersions:{event,public,revision},refetchUrl}`; 422 carries `{fields:[{path,code,message}]}`. Never return a private refetch URL to anonymous guests. The frontend preserves local unsaved input on every error and compares against server state before retry. Do not give a seat or price mapping that has not been reconfirmed by the guest.

`SEAT_AUTHORING_ENABLED` and `PUBLISHED_REVISIONS_ENABLED` default off independently. No navigation or action appears as live until migration 007 and A3 media are connected, Frontend explicitly agrees this contract, and browser→API→Neon checks pass. Tests must cover legacy A4 backfill, active-pointer atomicity, owner/editor/foreign/disabled permissions, two-tab version conflict, pending/return/approve state machine, simultaneous approval and idempotent lost response, seat identity preservation versus geometry reset, gaps/overrides/duplicate labels, 10,000-seat pagination, mixed GA/seat plus shared/per-occurrence pools, accessible seats without eligibility, DST and media references, old quote after approval, new quote against new version, immutable old/new receipts, cancellation and service outages. Browser checks at 320/390px, keyboard, 200% zoom and reduced motion verify the authoring and review tasks. No test can establish real sale, reservation, payout or email delivery because A6 implements none.
