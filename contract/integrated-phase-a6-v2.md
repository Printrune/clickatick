Date: 2026-10-21. Brief `brief/project.json` v104. This document incorporates `frontend/integrated-phase-a6-contract-review-v1.md` and is authoritative where it amends `contract/integrated-phase-a6-v1.md`; every unamended v1 security, persistence, state and activation rule remains. ## 1. Exact revision mutation projections

Define `RevisionView` as the **exact** `data` object of `GET /api/v1/organizers/{org}/published-events/{eventId}/revisions/current` in v1:

```json
{"event":{"id":"uuid","status":"published","activeVersion":2,"eventVersion":4,"publicUrl":"/events/uuid"},"revision":{"id":"uuid","basePublicVersion":2,"version":3,"status":"draft","draft":{},"updatedAt":"ISO","updatedByLabel":"Team member","submittedAt":null,"reviewedAt":null,"returnNote":null},"permissions":{"editRevision":true,"submitRevision":true,"reviewRevision":false,"cancelEvent":false},"changes":[{"path":"title","kind":"material","before":"Old title","after":"New title"}],"validation":{"errors":[],"warnings":[]}}
```

All fields appear with explicit nulls or empty arrays. The `draft` is the complete canonical A2 input, not an arbitrary client patch. `eventVersion` is `public_events.version` (status/concurrency); `activeVersion` is approved content version. `permissions` are derived from the current member and revision state, never copied from a previous response. `validation` is recomputed from the returned revision content. A role-safe display label never exposes Clerk ID or email. The change list may be empty on creation/no-op.

Successful `POST .../revisions` returns **201** `{data:RevisionView,error:null}` with revision version 1. Successful `PATCH .../revisions/{id}` returns **200** `{data:RevisionView,error:null}` after changed or canonical no-op save; a no-op leaves `revision.version` and `updatedAt` unchanged and still returns current diff/validation. Successful `POST .../submit` returns **200** `{data:RevisionView,error:null}` with `status:"pending_review"` and an updated `submittedAt`; revision version increments once. Successful `POST .../return` returns **200** `{data:RevisionView,error:null}` with `status:"returned"`, persisted note and updated `reviewedAt`; version increments once. An identical idempotent retry returns the originally committed HTTP status and body, not a projection assembled after subsequent writes. `GET current` and each mutation must share one projection implementation so they cannot disagree about permissions or validation.

If an open revision already exists, `POST` with a **different** key returns 409 `{data:null,error:{code:"REVISION_EXISTS",message:"A private revision already exists for this event.",revisionId:"uuid",editUrl:"/dashboard/{org}/published-events/{eventId}/edit"}}` to an active member who may read that event. It reveals nothing to a nonmember, who still gets 404. `editUrl` is server-built from validated UUIDs; the client then GETs current before editing. Same key/body replay wins before this conflict. A stale revision PATCH or action returns `REVISION_VERSION_CONFLICT` with `currentVersions:{event,public,revision}` and this member-safe `editUrl`; preserve local unsaved changes for comparison. Approve keeps its v1 result DTO because it advances public state and closes the revision, rather than returning a working `RevisionView`.

## 2. Section order and legacy A2 seat drafts

Section `position` is **derived from the zero-based index** in `seating.sections[]`; it is not an input field and clients must not send it inside a section. The server projects `position` to private seat-map and diff DTOs and writes normalized public section rows at approval. Reordering `sections[]` changes display order, not section identity or the identity of unchanged seats. The seat identity key is `(section UUID,row number,seat number)` within a public event, subject to explicit `geometryReset`; section position and name are not part of that key. Generated labels use the section name and row/seat numbers. Reordering can change how the map is arranged, so the change review lists it, but it preserves UUIDs. If a rearrangement changes a seat's physical meaning, the editor must mark that section `geometryReset:true` and the owner review shows that all its seat IDs will change. The backend cannot infer physical equivalence from order alone.

A6 extends the strict A2 parser and 256 KiB create/PATCH validator **before** enabling seat authoring. Accepted section shape becomes `{id?,name,rows,seatsPerRow,seatTierId,accessibleSeats,removedSeats?,seatOverrides?,geometryReset?}`. `removedSeats` and `seatOverrides` omitted in old A2 drafts normalize to `[]`; omitted `geometryReset` normalizes to `false`. The legacy `accessibleSeats` field remains and its original coordinates preserve order/meaning after canonical coordinate sorting. The canonical GET projection always emits all three new fields, while a legacy A2 PATCH that replaces a nested `seating` object without them is normalized in the server transaction rather than rejected or interpreted as a geometry reset. Unknown other keys still reject. The server does not rewrite a saved v1 draft merely on GET; its first valid A6 save writes the normalized shape with optimistic `expectedVersion`. This migration must be tested with actual pre-A6 draft JSON and with the original A2 PATCH route, not just a new revision route. Section count/seat count/size bounds remain unchanged.

The v1 phrase tying label uniqueness to `(section position,row,number)` is replaced: only `(section UUID,row,number)` is the machine identity. A human label should include section name; two sections with the same name and identical row/number remain distinct via section ID and are disambiguated in the UI with section order or a short stable suffix. Reordering alone cannot silently regenerate public seat IDs. Removal/recreation or explicit reset still creates new IDs; old version/receipt seats remain intact.

## 3. Stale demo quote reads and checkout errors

`GET /api/v1/events/{eventId}/demo-quotes/{quoteId}` continues to return the **original no-PII quote**, unchanged, even when stale. For an approved content update its exact extension is:

```json
{"data":{"quote":{"id":"uuid","eventId":"uuid","occurrenceId":"uuid","eventVersion":2,"items":[{"tierId":"uuid","name":"Adult","quantity":2,"unitPriceMinor":2500,"seats":[{"id":"uuid","label":"Front · A12","sectionName":"Front","accessible":false}],"unassignedQuantity":1}],"ticketSubtotalMinor":5000,"platformFeeMinor":500,"organizerShareMinor":4500,"amountChargedMinor":0,"currency":"USD","expiresAt":"ISO","demo":true,"seatSelectionReserves":false},"state":"event_changed","recovery":{"code":"EVENT_VERSION_CHANGED","currentEventVersion":3,"detailUrl":"/events/uuid"}},"error":null}
```

The remaining A4 quote item fields and values are preserved exactly; the sample is illustrative. No new price, tier, occurrence or seat mapping appears in `recovery`. The old quote is display-only and cannot create a new checkout. Its 15-minute expiration remains unchanged and is not renewed; if both stale and expired, return `state:"event_changed"` while checkout may return `QUOTE_EXPIRED` after checking the event version. The UI still sends the guest to current selection. A cancelled event uses distinct `state:"event_cancelled"`, `recovery:{code:"EVENT_CANCELLED",currentEventVersion,detailUrl}` even if its content version also changed. A missing or mismatched event/quote returns 404, not a stale state. The response remains `Cache-Control:no-store` and `Referrer-Policy:no-referrer`.

For a **new** `POST /api/v1/events/{id}/demo-checkouts` attempt against a stale quote, return **409** `{data:null,error:{code:"EVENT_VERSION_CHANGED",message:"The event changed. Review the current ticket and seat details before continuing.",quoteEventVersion:2,currentEventVersion:3,detailUrl:"/events/uuid"}}`. This extension reveals no private draft or automatic mapping. A cancelled event retains A4 `EVENT_CANCELLED` and its safe detail URL; unknown or mismatched quote is 404. Checkout idempotency replay of a **previously successful** request still returns its original receipt before current version/cancellation/expiry checks. A stale quote with a different new key cannot checkout even if its seat IDs survived the revision.

## 4. Versioned media and receipt images

The stable A4 public media route `GET /api/v1/events/{eventId}/media/{slot}` (`slot=business|event-location|cover`) resolves the **active approved version** on each request. Public catalog/detail `coverImageUrl` and `businessLocation.photoUrl`/`eventLocation.photoUrl` keep that existing active URL shape; `GET /api/v1/events/{id}` adds `activeVersion` so frontend can key/revalidate images after approval. The active media endpoint sends `Cache-Control:no-store` until invalidation of cached older images is proven. It never resolves a private revision image.

Add `GET /api/v1/events/{eventId}/versions/{version}/media/{slot}` for image slots of an immutable **approved** version, using the same allowlisted MIME, server-only private Blob lookup, response headers, same-location fallback and 404/503 behavior as A4 media. It does not expose version content JSON or an unapproved revision. The version path integer is bounded and checked against an approved row; nonexistent event/version/slot is 404. A historical image URL is same-origin and safe to share, but private Blob URL/path stays server-side. No query-string asset token. Media deletion checks all approved version references, open revision refs and receipt refs before removal.

New receipt `eventSnapshot.media` is either `null` or `{slot:"cover"|"event-location"|"business",eventVersion:integer}`. The server derives `imageUrl` in the public receipt response as `/api/v1/events/{eventId}/versions/{eventVersion}/media/{slot}` only when the approved version contains that slot and it is an image. It does **not** persist a Blob path, signed URL or arbitrary client URL. If there is no cover, prefer event-location then business photo; selection is made at checkout and frozen in the snapshot. Replacement of active listing media cannot change a receipt image. A missing old asset yields `imageUrl:null` plus a labeled image-unavailable fallback while captured textual details remain. Legacy A4 receipts with no captured version/media show no historical image; they do not use the current listing image as if it were original. A future video/media contract requires its own delivery rules; this A6 receipt image projection is image-only.
