# Integrated ticketing Phase A3 — private event media contract v1

Date: 2026-10-21. Prospective contract against `brief/project.json` v96 (media decision recorded at v95; v96 added staff invitation channels). Frontend agreement and a PM handoff are required before implementation. A1 Clerk/Neon identity and A2 private event drafts remain the base. This phase enables **private** event images only; it does not publish an event, accept payment, or deliver a ticket.

## Owner decision and scope

The organizer keeps each successfully uploaded private photo until they explicitly delete it. An unattached image is still the organizer's image and is never purged merely because it is unused, old, or replaced. Only incomplete upload attempts, for which the API never returned an asset, may be cleaned up automatically. The original conversation image stays in device storage until the organizer explicitly discards that device draft. Uploading and attaching it do not clear that source.

A3 keeps A2's `EventDraftInput`, event URLs, and `photoAssetId`/`coverAssetId` fields. It changes only the currently disabled private asset routes, adds list/delete, and makes A2 event writes coordinate attachment references transactionally. Brand owners may upload, attach, detach and delete for now. The owner has approved editors preparing changes, but invited-editor identity and rights are not implemented; do not enable editor writes as a side effect of this phase. Active brand viewers may list and preview. Every route derives the Clerk subject and checks active brand membership; foreign asset IDs look missing (404), and disabled members get 403.

## Storage and migration 003

Use the existing **private** Vercel Blob store and Neon `organizer_media_assets` from migration 002. Add upload lifecycle states `pending|ready|deleting|deleted`, `kind`, positive `version`, a per-brand+subject upload idempotency key/hash, reservation expiry, and unique `(organizer_id,id)`. Add `organizer_event_asset_refs(organizer_id,event_id,slot,asset_id)` with `slot=business|event-location|cover`, a unique `(organizer_id,event_id,slot)`, and composite foreign keys to the same-brand event and asset. Backfill references from every A2 draft snapshot before relying on the table; reject or quarantine a malformed legacy snapshot rather than silently lose its attachment. The A2 create/import/PATCH adapters must update snapshot and references in one Neon transaction. Attaching locks the asset row, checks `state=ready` and brand ownership, and then writes the reference. Deleting locks the same row and requires zero references, so attach and delete cannot race.

Blob path is server-generated from the brand and asset UUID, for example `brands/{organizerId}/assets/{assetId}.webp`; no filename, user text, or remote URL controls it. Neon stores the private path, verified MIME and dimensions, output byte length, alt text, state, creator subject and timestamps. API responses never expose the path, Blob URL, token or raw provider error. A3 needs no public Blob ACL, direct browser Blob credential or generated public image URL. `BLOB_READ_WRITE_TOKEN` and `DATABASE_URL` stay server-side; missing config returns 503.

## Exact routes and envelopes

Base: `/api/v1/organizers/{organizerId}/assets`. JSON endpoints retain A1/A2 `{data,error}` and `Cache-Control:no-store`. For successful binary preview, return the image bytes with the headers below rather than JSON. UUIDs are canonical lowercase on output.

| Route | Request | Success |
| --- | --- | --- |
| `POST /assets` | Same-origin multipart/form-data with exactly one `file`, `kind` (`business|event-location|cover`), `altText` (0–200 characters), and `uploadId` UUID. No data URL. | 201 `{asset:{id,kind,mime,byteLength,width,height,altText,createdAt,previewUrl}}` |
| `GET /assets?cursor=&limit=` | Active member. `limit` 1–50, default 20. Opaque `(createdAt,id)` cursor. | 200 `{assets:[AssetSummary],nextCursor}`. Only ready assets; oldest/unused uploads remain listed until deleted. |
| `GET /assets/{assetId}` | Active member; no bearer capability in URL. | 200 streamed private image; missing, foreign or deleted asset 404. |
| `DELETE /assets/{assetId}` | Same-origin owner request with JSON `{confirmDelete:true}` and `If-Match` asset version/ETag from list or upload. | 204 after Blob deletion **and** Neon `state=deleted`; referenced asset 409 `ASSET_IN_USE` with reference count, stale version 409. Repeated DELETE of an already deleted own asset returns 204. |

`AssetSummary` has `{id,kind,mime,byteLength,width,height,altText,createdAt,previewUrl,referenceCount,version}`. `previewUrl` is always the authenticated same-origin route `/api/v1/organizers/{organizerId}/assets/{assetId}`. List defaults to most recent first, stable by `(createdAt,id)`. The server never returns a signed Blob URL to the browser. If a future implementation chooses short-lived signed URLs, that is a new agreed contract; A3 uses authenticated server streaming.

Use `POST` `uploadId` as a stable retry key. The server hashes the normalized `kind`, `altText`, image bytes and MIME. Same brand+subject+key+hash replays the same 201 asset while it is ready; same key with changed payload returns 409 `IDEMPOTENCY_CONFLICT`; a pending attempt returns 409 `UPLOAD_IN_PROGRESS` with a short `Retry-After`; a previously deleted asset does not resurrect and returns 409 `UPLOAD_ALREADY_DELETED`. A client preserves `uploadId` only for a retry of unchanged input.

## Image processing and bounds

Stream/read multipart under an absolute **2 MiB raw file** cap and a modest multipart overhead cap (2 MiB + 16 KiB); reject as soon as the cap is crossed. Accept JPEG, PNG or WebP only after checking bytes and decoding, not from filename or browser MIME alone. Decode with limits: each dimension 1–4096 and at most 12 million pixels. Normalize orientation, strip EXIF/metadata, and re-encode to JPEG or WebP at at most 2 MiB. Reject decompression bombs, animated images, malformed/truncated files, SVG, HTML and remote URLs. Do not persist originals, thumbnails or base64 in Neon. `kind` describes intended slot, but attaching uses asset ID and brand membership; it does not grant extra access.

Return 400 with field errors for invalid image/type/dimensions, 413 for raw/multipart/output size, 401 unauthenticated, 403 disabled/insufficient role or wrong origin, 404 foreign brand, 409 conflicts, 429 quota/rate limit and 503 unavailable dependencies. Do not expose image bytes, EXIF, private paths or provider errors in logs. Upload/preview/delete should use Node runtime to support bounded processing and server Blob SDK.

## Quota and failure reconciliation

Proposed A3 safety caps: **100 ready or pending assets and 100 MiB reserved/ready bytes per brand**, **10 new uploads per brand per hour**, and **2 pending uploads at once per brand**. Reserve 2 MiB for each pending attempt; replace that with actual output bytes only when it becomes ready. `deleting` assets continue to count until Blob deletion succeeds. These are application limits, not claims about Vercel's free-plan allowance; the PM should confirm the product cap before code. A delete frees an asset/bytes only after Blob deletion succeeds. Quota reservations and upload counts live in Neon and are enforced atomically, including parallel requests. A stable idempotent replay does not consume a new rate slot. Return 429 `UPLOAD_LIMIT_REACHED` with `Retry-After` for the hourly/concurrent cap and 413 `BRAND_MEDIA_QUOTA` for the storage cap. No auto-deletion of successful uploads to make room.

Order upload as: authenticate and validate; atomically reserve a `pending` row and quota; put a private Blob at the deterministic path; atomically mark the row `ready` with verified output metadata; then return 201. If put fails, release the pending reservation. If put succeeds but Neon finalization fails, attempt to delete that **uncommitted** Blob. If cleanup itself fails or the function crashes, keep a pending row with the exact path; a bounded retry/reconciliation job may delete **only expired pending** Blob objects after checking they were never marked ready, then release the reservation. This is failure compensation, not retention cleanup. Never schedule deletion of ready unattached assets.

Order explicit delete as: verify owner and `confirmDelete`, lock asset, check zero references and version, set `deleting`, call Blob delete, then mark `deleted`. If Blob delete fails, retain `deleting` with reservation charged and retry only that explicit delete operation; return 503 and do not claim success. A retry remains idempotent. To delete an attached image, the organizer first clears or replaces every relevant `photoAssetId`/`coverAssetId` through versioned A2 PATCH, sees it become unattached, and then confirms Delete. The UI must not silently detach or delete as part of image replacement. A future published-event reference must also block deletion until an explicit published-media policy is agreed.

## Private preview

Lookup by brand and asset ID in Neon first; require `state=ready`. Fetch from private Blob with server credentials and stream to the response. Send the verified allowlisted `Content-Type`, `Content-Length` if known, `Content-Disposition:inline`, `Cache-Control:private, no-store`, `X-Content-Type-Options:nosniff`, `Cross-Origin-Resource-Policy:same-origin` and `Vary: Cookie`. No public CDN cache or cross-origin embedding. If Blob is missing, return 503 `MEDIA_UNAVAILABLE` and alert operations; do not return a broken private URL or a public fallback. The browser uses the same-origin preview route as the image source. A2's local source image remains available during a failed upload or preview.

Tests must cover upload/replay/conflict, raw/pixel limits, EXIF removal, brand isolation, viewer read versus owner write, attach/delete race, referenced delete 409, explicit delete retry after Blob failure, pending-only compensation, quota concurrency, missing credentials and retained browser source. An end-to-end test uses configured test services before claiming a live private upload works.
