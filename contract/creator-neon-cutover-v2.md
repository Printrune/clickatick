# Creator-to-Neon cutover contract v2

Date: 2026-10-21. Source: `brief/project.json` v105, `backend/legacy-publishing-cutover-v1.md`, `frontend/creator-neon-cutover-review-v1.md`, approved A1/A2/A4 contracts. **Prospective revision for Frontend agreement; no code or service changed.** This supersedes v1 where clarified below. `/creator` voice and text conversation, local draft, visual scene and review remain. New marketplace events require Clerk sign-in, brand ownership and owner review before Neon publication. Payment, admission, email delivery and referral payout remain unavailable. ## User journey and state ownership

1. The visitor speaks or types in `/creator`. The browser maintains `ticketnest-draft` with the existing validated legacy draft, conversation state, scene/media and any failed answer. `/api/chat` and `/api/speech` retain their existing AI/speech capability and error behavior. No Clerk session is required to converse or review locally.
2. Local **“Review tickets”** and **“Save to brand draft”** remain separate actions; the save handoff is also available within the review. Review can edit the local record before selection. Save does not publish, create an admission ticket or send draft content to a URL. It sets only the existing `clickatick-import-creator=1` session marker, then navigates to `/dashboard?source=creator`. Remove the direct `Publish demo listing` action and obsolete email/local login dialog in the same client release as the tested handoff. `clickatick-publish-intent-*` is no longer created by new clients.
3. `/dashboard` calls `GET /api/v1/me`. A 401 displays sign-in; `/sign-in` uses Clerk Google/email and a fixed safe return to `/dashboard`. A 503 shows unavailable state and keeps the browser draft. The old `ticketnest-session` cookie is ignored; it is not transformed into a Clerk account and cannot authorize Neon writes. In **creator-import mode**, only active brands whose returned `role` is `owner` are selectable under the current A2 import authorization. Editor/viewer brands may be listed as disabled with “Only the brand owner can save this draft here”; they never navigate to an import that is expected to fail 403. If there is no eligible owner brand, offer brand creation. Even one eligible owner brand is selected explicitly. The normal `/dashboard` chooser keeps all accessible brands and their regular links. Brand creation/selection then navigates to `/dashboard/{organizerId}/events/new?source=creator`. Cancel or back returns to `/creator` with the local record intact. A1's current `permissions.createEvent:false` projection is stale for A2 and must not hide an owner brand; the A2 server authorization remains decisive.
4. `OwnerDraftEditor` reads the **unchanged** source record from the device and calls the existing brand-scoped import endpoint. A successful import returns a private draft and field-specific warnings; it does not clear the local record or claim local photos transferred. The editor opens `/dashboard/{organizerId}/events/{eventId}`, shows missing address/pin/photo/ticket/disclaimer details, and saves further changes using A2 PATCH. Only the brand owner can import and publish under the currently implemented rights; any later editor capability must follow the agreed staff contract.
5. The owner reviews the saved draft and calls A4 publication. Only a successful A4 response creates `/events/{id}`. Buyers there can use the zero-charge A4 demo quote/checkout, never a real purchase. Failed sign-in, import, photo upload, validation, publish, or navigation leaves the device draft and previously saved private draft available for retry.

The source of truth is browser storage **before import**, Neon `organizer_event_drafts` **after import**, and Neon `public_events` **after owner publication**. The device copy is retained until the organizer explicitly discards it. Blob legacy listings and receipts remain a separate historical system; no implicit ID or owner mapping is inferred.

## Exact active API contract

All A1/A2/A4 JSON endpoints use `{data:<shape>,error:null}` on success and `{data:null,error:{code,message,fields?,currentVersion?,publicUrl?}}` on error. No draft, image data or creator token is placed in the query string. Same-origin checks apply to mutations. Private endpoints derive the Clerk subject on the server and verify active brand membership; brand IDs and draft IDs alone grant no access.

| Step | Request | Response and transition |
| --- | --- | --- |
| Auth/brand list | `GET /api/v1/me` | 200 `{data:{userId,brands:[{id,slug,name,role,permissions,dashboardUrl}],nextAction},error:null}` under A1; 401 `SIGN_IN_REQUIRED`, 503 `AUTH_UNAVAILABLE` or `DATABASE_UNAVAILABLE`. Only active memberships appear. The browser never uses `/api/auth`. |
| Brand creation, when chosen | `POST /api/v1/organizers` with `{name,slug,idempotencyKey:UUID}` | A1 201, same-key replay, or A1 field/conflict errors. Stable key retained across an unchanged retry. |
| Creator import | `POST /api/v1/organizers/{org}/events/import-draft` with `{sourceDraft:LegacyClickatickDraft,idempotencyKey:UUID}` ≤2 MiB | A2 201 `{data:{event:OwnerDraft,warnings:[{path,code,message,localMediaSlot?}]},error:null}`. Same key/body replays same private event. Changed source draft gets a new key. 401/403/404/409/413/422/503 leave the local source intact. No `publicUrl`. |
| Private edit | `GET/PATCH /api/v1/organizers/{org}/events/{eventId}` | A2 `OwnerDraft`, versioned PATCH `{expectedVersion,changes}` and warnings. Changed address clears its prior pin; photos attach only through an approved, ready private asset ID. |
| Owner publication | `POST /api/v1/organizers/{org}/events/{draftId}/publish` with `{expectedVersion:integer,idempotencyKey:UUID}` ≤8 KiB | A4 201 `{data:{event:{id,status:'published',version,sourceDraftId,publishedAt},publicUrl:'/events/{id}',warnings:[]},error:null}`. Identical key/body replay resolves uncertain responses. Required photo/address/pin, future date, inventory, tier, ticket format, reviewed disclaimer and refund policy are validated server-side. Denied/incomplete/disabled states never generate a public URL. |
| Public detail and buyer demo | `GET /api/v1/events/{id}` and A4 quote/checkout/receipt routes | Only tested Neon public events; zero amount charged, no seat hold, sale, admission or buyer PII. |

Import-specific error behavior is inherited from A2. Client validation is advisory; the server validates the full source draft, canonical mapping, brand ownership and media references. A warning such as `LOCAL_IMAGE_UPLOAD_NEEDED` keeps the private draft incomplete and the original data URL on the device. A creator may resume another brand selection without silently copying the draft to a different brand. The browser keeps a stable import key for the same selected brand and canonical source record through network retries; a changed draft or chosen brand gets a new key.

## Legacy routes and rollout responses

At cutover, `POST /api/demo/listings` stops accepting **new** anonymous Blob listings. Exact legacy-route response: HTTP 410 `{error:'Save this draft to a brand to publish it after review.',code:'LEGACY_PUBLISHING_CLOSED',saveDraftUrl:'/dashboard?source=creator'}`, `Cache-Control:no-store`, with no write and no creator cookie. This string `error` shape is intentional: a cached v1 `Workspace` does `new Error(result.error)` and must show useful recovery copy. An old `clickatick-publish-intent-*` retry receives 410 even if the same ID already exists; its local draft remains recoverable. The new client never calls this route.

Historical `/listing/{id}` becomes a **read-only snapshot**: the public listing and existing `/receipt/{id}` confirmations remain readable by direct link. No new legacy demo checkout or receipt, artwork generation, marketing draft/refinement/approval/revocation, or other legacy mutation is allowed after cutover. Specifically, close `POST /api/demo/listings/{id}/checkout`, `POST /api/demo/listings/{id}/artwork`, `POST/DELETE /api/marketing/{id}`, `POST /api/marketing/{id}/refine`, and `POST /api/marketing/{id}/approve` with the same 410 legacy string-error form and no write. Existing `GET /api/marketing/{id}` may continue as a creator-token-protected read of saved work; it does not grant mutation. Remove/disable `DemoCheckout`, `CreatorPromotionPanel` actions and marketing editor controls from the legacy detail page, show “Earlier demo listing. No new demo orders are available,” and retain only a public-link copy action if useful. Any old cached client receiving 410 must keep its local selection/draft and show the server message; it must not retry indefinitely. Closing those mutation routes does not erase existing Blob listing, receipt or marketing data. No Supabase/Blob data is copied into Neon here.

`POST /api/listings` (Supabase/local legacy) likewise returns the string-error 410 once the creator has no caller; `/api/auth` no longer starts OTP or local sessions. A retired auth endpoint must never sign out a Clerk session. `PUBLISHING_ENABLED`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `lib/services.js` `database()/session()`, local PGlite publishing and Supabase `published_events` fallback can then be removed. Preserve `sameOrigin` as a neutral utility for chat/speech/legacy reads and preserve AI/speech capability projection. Keep `eventPublicationErrors` while `lib/demo-validation.mjs` imports it; delete only obsolete `eventPublicationPath`, `publishedEventPath` and `publicationPayload` after their last callers are gone. Historical SQL/docs are archived evidence, never Neon migrations.

## Public catalog and URL boundary

`/` and `/discover` show the Neon `GET /api/v1/events?cursor=&limit=` catalog as the **single canonical catalog** only after connected A4 public detail, media and buyer-demo verification. The current `NewDemoCatalog` duplicate section and `NEXT_PUBLIC_NEON_DEMO_CATALOG_ENABLED` dual-display behavior are removed in that release. New cards link exclusively to `/events/{id}`. **Owner decision in v105:** old Blob `/listing/{id}` and `/receipt/{id}` remain direct-link-readable but disappear from `/`, `/discover`, site search and new catalog results. No redirect from a legacy UUID to Neon occurs without an explicit migration map. Catalog outage shows a real error state rather than an empty-events claim.

Homepage reads the first Neon page with `limit=20` and displays at most six featured cards, all pointing to `/events/{id}`. `/discover` loads `limit=20`, renders the returned `nextCursor` as a “Load more events” action, appends each subsequent page once, and stops when `nextCursor:null`. Existing free-text/title/location and type filters apply only to **loaded** rows. The input label and results text must say “Search loaded events” / “No matches in loaded events. Load more events to continue searching” while a cursor remains. Do not claim a site-wide search or an exact total count. Cursor fetch failure keeps prior rows and offers retry with the same cursor; deduplicate event IDs across pages. A server-side search endpoint is a later contract, not silently simulated by filtering the first page.

One **server-owned** gate is named `CREATOR_NEON_CUTOVER_ENABLED=false` by default. It controls server-rendered creator completion mode, canonical catalog source and **all** old Blob/Supabase/local mutation closures. It is never `NEXT_PUBLIC_*`; an old cached client still receives 410 from the server after activation. Gate off retains current behavior; gate on enables the new creator handoff, Neon-only catalog and 410 legacy mutations. A failed Neon read while on returns unavailable, never an automatic Blob fallback. Ship a compatible server and dual-mode client while the gate remains off; test both modes locally, then verify connected Clerk/Neon/media/A4 public and buyer flows. Roll the gate on only after the new creator client bundle and 410 responses are deployed together. During a rolling deployment, a cached old client may still display its previous publish button; POST returns the string-error 410 with the existing local draft intact and the existing “Save to brand draft” footer recovery path. A new client served before the gate flip continues the old mode. No deployment may turn on the canonical Neon catalog while anonymous Blob writes remain open. If rollback is needed after new Neon events exist, turning the gate off would reopen old writes and hide Neon events; rollback must instead restore the previously working new-mode release or deliberately keep the old writes closed. This contract does not claim activation or a connected service.
