# A3 v6 backend addendum v1

Date: 2026-10-21. Source: `brief/project.json` v104, agreed A3 v4/v5/v6 contracts and PM follow-up. This extends `integrated-phase-a3-media-v6-implementation-v1.md`. No connected service, deployment, or Blob object was changed. All upload and playback flags remain absent/false by default.

## Added behavior

- `lib/integrated-phase-a3-media-v6-recovery.mjs` provides an operator-invoked batch of at most 50 expired reservations. It locks each asset/reservation, inspects both possible private paths, and releases reserved bytes only when both are absent after a one-hour grace period. An object, uncertain Blob read, or in-progress verification leaves capacity charged and a visible `reconciling` asset with a failure code. The pass is idempotent. It has no automatic schedule and cannot silently discard an uploaded object.
- `lib/integrated-phase-a3-media-v6-mp4.mjs` inspects bounded MP4 track/sample-description boxes. It accepts one H.264 `avc1` video track with AVC configuration and one AAC-LC `mp4a` audio track; it rejects H.265, AC-3, fragmented/ambiguous structures, malformed boxes and unsupported entries. `processCompletedVideo` verifies the private Blob head and exact declared size, inspects the bytes, then commits `ready` and the physical-byte ledger in one transaction. A rejected codec stays unready in operator-visible `reconciling` state with its reservation charged. The direct-upload callback can call this path only when the separate video upload gate is explicitly enabled.
- `GET`/`HEAD /api/v1/organizers/{organizerId}/assets/{assetId}/video` require active brand membership, ready video state, and the separate default-off playback gate. The private handler serves full GET or one `Range` request, returns exact `206`/`Content-Range`, returns `416` for invalid/unsatisfiable ranges, and refuses an upstream Blob response that ignores a range. It streams without buffering the response and sets private no-store headers. There is no public video playback route.
- Capability projection now reflects separate image upload, video upload and video playback flags, while retaining the existing DTO keys.

## Remaining activation blockers

Clerk, Neon and the private Vercel Blob store are not connected in this checkout. The Vercel Blob SDK range behavior is unverified against the actual private store; its published `get` type describes a 200 stream, so playback intentionally fails closed if a range is ignored. No real MP4 fixture or connected 100 MB direct upload was exercised; the strict parser supports a limited H.264/AAC-LC subset and needs real-device fixtures before activation. The recovery pass has no scheduled worker or operator route; run it only after establishing a protected operational trigger and connected-store monitoring. Any legacy/parallel Blob writers must be coordinated before the global ledger gate can be enabled. Public video delivery, client video UI, poster/captions, and connected end-to-end playback are outside this addendum. Do not turn on the video flags from these local tests alone.
