# Phase A1 backend implementation v1

Date: 2026-10-20. Brief v93; frozen contract `contract/integrated-phase-a1-v2.md`; PM handoff `handoffs/003-pm-phase-a1-agreement.md`.

Implemented fresh Neon migration `backend/migrations/001_integrated_phase_a1.sql` for brands, Clerk-subject memberships, idempotency records and a shared create-brand rate bucket. `lib/integrated-phase-a1.mjs` validates the exact brand body, origin, bounds, identity, membership and error envelope. `lib/integrated-phase-a1-runtime.mjs` adapts Clerk `auth()` and Neon's HTTP SQL driver; brand+owner+idempotency creation uses one SQL statement so a partial brand is not committed. `proxy.js` runs Clerk middleware only for organizer routes and bypasses it when credentials are absent. Added `GET /api/v1/me`, `POST /api/v1/organizers`, and `GET /api/v1/organizers/[organizerId]`. Added A1 variables to `.env.example`. Frontend owns the conditional provider and UI; dependency installation was coordinated with Frontend, which added `@clerk/nextjs` and `@neondatabase/serverless`.

The backend returns 503 `AUTH_UNAVAILABLE` or `DATABASE_UNAVAILABLE` when the corresponding service is unconfigured/unavailable. It does not claim a Clerk account, Neon database, signed-in user or stored brand exists. Public marketplace, creator, Blob demo routes and their data were not changed. The brand dashboard response says “Event management is being connected.” It does not invent event counts or sales.

Verification: `node --test tests/integrated-phase-a1.test.mjs` — 6 passed, 0 failed. PGlite executed the actual migration and SQL adapter, covering zero/multiple brands, create/replay/conflict, slug collision, origin/input checks, cross-brand denial, disabled membership, rate limit and route 503 behavior. `pnpm run build` passed after an elevated retry; the first sandboxed build failed solely because Windows denied Turbopack a junction to an existing `@electric-sql/pglite` package. The successful build compiled all new routes and Proxy. No real Clerk/Neon integration test or migration against Neon was run; connecting credentials, applying the migration to a fresh database, browser sign-in and service verification remain before A1 can be called live.

Security limits: API role projection exposes only A1 capabilities. A1 creates owner memberships only; staff invitations and event writes remain disabled. Idempotency records persist until future cleanup of expired records; the unique key remains safe to replay meanwhile. Production rate limits and free-plan allowances must be observed after integration. No payment, admission ticket, email delivery or external send was added.
