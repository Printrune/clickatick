# Backend review of integrated promotions and referrals v1

Reviewed against `brief/project.json` v107, the Lovable source audit, A4 quote/checkout, and A6 versioned event/receipt code. **Amendments required before Backend agreement.** The server-priced integer-cent model, zero-charge distinction, owner-controlled referral rate, and no demo redemption count are sound.

1. **Make the active A6 write path explicit before extending it.** `lib/integrated-phase-a4-runtime.mjs` currently calls A4 `createDemoQuote` and `checkoutDemoQuote` even when `PUBLISHED_REVISIONS_ENABLED=true`; only quote/receipt reads choose A6. The prospective promotions quote must use A6 `public_version_*` prices, seats, pools and `active_version`, and checkout must preserve the A6 immutable event snapshot. Repair and test the write-path selection first. The promotional contract should name the versioned quote/checkout functions as the extension point and forbid a second price path.
2. **Freeze code terms in the quote.** Store promotion ID/version, normalized code, scope, discount kind/value, and referral-code ID/version in the immutable quote selection or response. At checkout, compare current promotion/referral version, active state, scope and expiration; a value, minimum, maximum-use, or scope edit must return `QUOTE_CHANGED` even if the code is still technically valid. Same-key successful receipt replay still wins. Define the existing quote-read `state`/recovery behavior for code changes too, without mutating the quoted price.
3. **Resolve the demo-only maximum-use rule.** Demo confirmations never redeem a code. Therefore `maximumRealRedemptions` cannot become exhausted through demo checkout. Specify that a configured real-use limit is display/configuration only in demo and that quote validation does not falsely report it as consumed. If real redemptions from another future system are considered, identify the authoritative ledger and transactional counter first.
4. **Specify exact API DTOs and conflicts before Frontend agrees.** The private promotion and referral create/patch/deactivate bodies, list cursor/limit, response envelope, activation review action, `expectedVersion`, idempotent replay status, and error fields are underspecified. State the quote's exact optional-key shape and whether absent, `null`, and empty code are equivalent. Preserve the current A4/A6 `{data,error}` envelope, 201 create/200 replay pattern, bounded same-origin input, and quote/receipt recovery fields. Separate quote `originalTicketSubtotalMinor` and `discountedTicketSubtotalMinor`; define legacy `ticketSubtotalMinor` as discounted only at the coordinated cutover.
5. **Constrain storage at the database boundary.** The optional event scope must have a composite `(organizer_id,event_id)` foreign key, not just two unrelated UUIDs. Make normalized code uniqueness case-insensitive in a transaction-safe way. Referral codes need the same brand/event constraint and collision policy. Do not store promoter name/email or return all active codes publicly. Spell out upper bounds for percent (0–10000 basis points), fixed amount, and code length, and the half-up integer rounding procedure.

No new owner decision is needed for the demo if PM and Frontend accept the stated assumptions: one ticket-only promo plus one referral attribution, no redemption/earnings/payment, and no add-on discount. Processing fee and actual promoter/payout rules remain future owner decisions for paid checkout.
