2026-10-18, brief v18. Backend specialist read role/shared rules and Gateway skill setup/spend references. PM approved existing frontend contract before implementation. Owner authorization to enable free-credit AI was relayed by PM.

Implemented server-only Vercel AI Gateway adapter. OIDC preferred, API key optional. AI_ENABLED and AI_FREE_TIER_CONFIRMED required; unset defaults stay disabled. AI_MODEL may be omitted or equal openai/gpt-4.1-mini. Base URL cannot be changed to another service. Live catalog confirmed exact model and JSON response_format support. This model's published token prices are $0.40/M input and $1.60/M output. Free-credit eligibility must be established by actual account request, not catalog presence alone.

Credit endpoint response documented as top-level balance and total_used string values. Adapter validates finite positive balance before completion and fails closed on unavailable balance. No purchased-credit setup, automatic top-up, provider keys, BYOK, fallback models, retries, SDK dependency or paid reporting added. Gateway 402 and 429 stop requests clearly. Secrets and raw upstream errors stay server-side. Existing route bounds inputs, validates parsed draft and reply; maximum output 1800 tokens. Hosted authentication/publishing and local database unchanged.

Supabase budget RPC removed from Gateway chat. This removes database coupling but also removes the former persistent application reservation. Provider free-credit exhaustion and owner-confirmed disabled top-ups are the spending boundary. Credit precheck is not atomic and cannot distinguish purchased credits. No durable distributed abuse controls. Keep deployment protection enabled pending public activation review. No guarantee that a Vercel alert or budget is a hard cap.
