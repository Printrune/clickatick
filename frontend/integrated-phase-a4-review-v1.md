# Frontend review — integrated Phase A4 v1

Date: 2026-10-21. Reviewed against `brief/project.json` v98, `team/shared-rules-v1.md`, `team/roles/frontend.md`, and the existing marketplace, discover, legacy listing and receipt routes. This is a prospective interface review; no A4 code was changed.

## Decision

**Agree with the product boundary and route split, subject to the interface amendments below.** The public `/events/{id}` and `/demo/receipts/{id}` paths can coexist with legacy `/listing/{id}` and `/receipt/{id}`. Owner-only publish/cancel, immutable public snapshots, no reservation, and cancelled-event receipts are appropriate. Do not begin independent Frontend and Backend implementation until the first three interface issues are resolved in a revised contract. The remaining release gates can be completed in parallel with preparatory UI work.

## Interface amendments needed before implementation

1. **Define exact JSON projections, not prose-only detail.** Specify `PublicEventDetail`, occurrence, tier, section, inventory and seat-page field names/nullability/sort order in a schema or example. Frontend needs a stable mapping from each tier's `seatPolicy` to compatible sections, a display label and configured counts for each section, and exact event/business location and media URL fields. “Coordinates” for seats must mean section-layout coordinates, not geographic coordinates. Include `{data,error}` envelopes for every public response or state explicit exceptions; the current catalog/quote examples omit them despite the general envelope rule. Provide field-error paths for publish preconditions, especially `PHOTO_NEEDED`, DST date, pin and disclaimer.

2. **Make required-seat selection practical at 10,000 seats.** A global 200-seat page sorted by section may require 50 sequential requests before a visitor can choose a seat in a later compatible section. Add `sectionId` (or compatible `tierId`) filtering to the seats route, with cursor semantics scoped to that filter. Return a stable seat display label and section/tier association per seat. Specify whether an optional-seat tier can mix assigned and unassigned places in a single quote; the current `seatIds.length <= quantity` implies yes, which the UI can support once stated plainly. The accessibility flag is informational and must never trigger a guest eligibility form.

3. **Add quote read for the separate checkout route.** `/events/{id}/demo-checkout?quote={quoteId}` cannot render or recover after refresh from a POST response alone. Add `GET /api/v1/events/{id}/demo-quotes/{quoteId}` returning the public, no-PII quote projection and explicit expired/stale/cancelled status, or keep review and checkout on one page without a quote URL. State whether the quote may be read/checked out from another browser or is bound to the anonymous demo cookie. Keep quote IDs opaque and rate limit reads.

4. **Specify seat labels on quote and receipt.** `seatIds` plus `seatLabels` should have a guaranteed identical order, or preferably each selected seat should be one `{id,label,sectionName,accessible}` object. Preserve the same immutable labels on receipt so later section changes cannot alter what a visitor saw. For an unassigned optional place, show quantity without inventing a seat label.

5. **Make the catalog cutover a named gate.** Current `/` and `/discover` call `readDemoCatalog()` and link to `/listing/{id}`. Specify a default-off flag or equivalent rollout setting for the Neon collection, its placement and explicit “demo” label, and failure behavior when Neon is unavailable. Keep legacy results separate without merging pagination/count/search claims. The new catalog endpoint has no search yet, so `/discover` should either show an unfiltered separate Neon section or perform bounded client-side search only over all fetched pages; it must not present page-one matches as all matching events. Turn the flag on only after the stipulated browser/API/data checks.

6. **Define recoverable error states.** Publish 422 field paths must map to editor controls; 409 stale draft or already-published responses need `currentVersion`/`publicUrl` or a specified refetch path. Quote/checkout 409 expired, cancelled, stale version and already-used must have distinct codes and a next action. A lost checkout response followed by retry with the same key should replay its committed receipt even if the event was subsequently cancelled; specify idempotency precedence. Public media 503 should leave readable event detail and an image fallback, not fail the page.

## Release gates and implementation sequence

The A3 quota decision and enabled private-photo upload are prerequisites for a successful publication, because venue photos are required. Anonymous per-cookie/global-event quota numbers and no-PII receipt retention remain owner decisions. PM should ask one at a time. Neither blocked service nor unapproved quota should be portrayed as working. UI can be built against contracted projections with unavailable/empty states first: owner review and field errors; public event and bounded seat selection; quote and checkout; shareable receipt; finally gated marketplace collection. Existing Blob pages stay operational throughout. Show “Illustrative ticket subtotal; $0 charged” and “No payment, seat reservation or admission ticket” at selection, checkout and receipt. For cancelled events, show the event and prior receipts with a clear cancellation notice but disable new quotes.
