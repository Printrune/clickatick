# U.S. event venue research — v1

Date: 2026-10-25. Brief: `brief/project.json` v109. Status: research, not an imported venue catalog.

## Finding

**VERIFIED:** No reviewed source promises a complete, current census of *all* U.S. event venues. “Venue” spans theatres, arenas, bars, museums, parks, temporary spaces, tour departure points, and organizer-defined meeting places. A place record also does not imply an upcoming event or tickets. The map should distinguish **venues** from **events happening there** and report source and freshness. Do not label coverage “all venues.”

## Recommended acquisition sequence

1. **Now:** Derive a venue record from each existing Ticketmaster event and each first-party Clickatick event. Keep `source`, `source_venue_id`, address, coordinates, `last_seen`, and a link to the active event. Group exact Ticketmaster venue IDs; do not use names alone. Show “events at this venue” only when current events exist. This fits the present API budget.
2. **Pilot bulk dataset:** Process one or two states from Overture files outside request handling. Filter to an explicit venue taxonomy (performing arts, live music, cinema, sports, convention/exhibition, attraction/activity), valid U.S. coordinates, plausible names, open status and confidence. Measure false-positive/duplicate rates with a manual sample per category and state before expanding. Keep source provenance and attribution. Estimate storage and import cost from that sample; no whole-U.S. cost is verified yet.
3. **Expand deliberately:** Process additional states in bounded batches, merge by source IDs and high-confidence spatial/name/address matches, keep ambiguous candidates separate. Add Foursquare OS or OSM only where the pilot finds coverage gaps and the combined license is reviewed. Add organizer-claimed venues with owner moderation and correction/removal routes. Run periodic refresh and deactivate stale/closed records.
4. **Provider upgrade:** If Clickatick needs a truly broad *event* catalog rather than venue locations, apply for Ticketmaster's [Discovery Feed](https://www.developer.ticketmaster.com/products-and-docs/apis/discovery-feed/) or other licensed feeds. Venue data by itself cannot create event inventory, ticket links, or affiliate revenue.

## SEO and AI-search implications

- Keep the interactive venue map useful to humans. Index a venue page only if it has verified location facts plus genuinely helpful, fresh event/activity information or original venue guidance. Avoid creating thousands of name/address-only pages. Google flags [scaled low-value content](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content?hl=en) and [doorway pages](https://developers.google.com/search/docs/essentials/spam-policies).
- For an event's leaf page, show accurate venue name/address and corresponding [`Event` structured data](https://developers.google.com/search/docs/appearance/structured-data/event). Do not mark a venue-only page as an event. Only include prices/availability if verified from the relevant seller. Cross-link city, venue, and event pages where each page adds distinct value.
- “GEO” is not a separate guaranteed ranking channel: factual, crawlable, attributable content and current event data are the safer foundation. Measure indexed pages, search traffic, event-click engagement and venue-data correction rate, not raw page count.

## Open gaps / decisions for PM

- Define the initial venue taxonomy and priority states. A theatre-only inventory and an “anything hosting an activity” inventory have very different scales.
- Obtain access to Overture/FSQ data and measure actual per-state volume, quality, and storage cost before promising national coverage.
- Confirm commercial use and attribution review for each combined source, especially if OSM records are merged into one database.
- Ticketmaster Discovery Feed, affiliate tracking, and any commission remain unapproved. Public API event links do not by themselves provide an affiliate commission.
