# Event map, activity planner, and search research — v1

Date: 2026-10-25. Brief: `brief/project.json` v108. Scope: consumer discovery of Clickatick and Ticketmaster events, with provider checkout for Ticketmaster. Evidence below is from primary sources reviewed 2026-10-25. This is product research, not legal clearance or a search-ranking promise.

## Recommendation

Build a **map plus accessible event list** for the current search area. Plot only events with verified coordinates and show those without coordinates in the list. Use clustered pins, explicit date/category filters, and links to existing event pages. Do not label it “all events”: the Ticketmaster Discovery API only allows deep paging through the first 1,000 results and has a default quota of 5,000 calls/day and 5 calls/second. Query by visible region using its `geoPoint`, `radius`, and `unit` filters, cache briefly, and combine results with Clickatick's published-event coordinates. `latlong` is deprecated. The API docs expose venue latitude/longitude. [Ticketmaster Discovery API](https://developer.ticketmaster.com/products-and-docs/apis/discovery-api/v2/)

Use a normal basemap provider with production rights. The previously chosen Google Maps **Demo Key is explicitly for prototypes, not production**; a production Google map requires a billed Maps Platform account. MapLibre is an open-source rendering library, but it does not provide free unlimited tiles. Community OpenStreetMap tile servers lack an SLA, prohibit bulk prefetch, require visible attribution, and may restrict commercial use. Keep the tile URL/provider configurable. [Google Demo Key](https://developers.google.com/maps/demo-key), [MapLibre GL JS](https://maplibre.org/projects/gl-js/), [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/)

For the planner, interpret “device ID” as a **random, first-party browser planner identifier** created only when the visitor saves an event. Do not fingerprint hardware or infer a permanent device identity. Store an anonymous plan against that identifier, or initially in local storage if cross-device/server persistence is unnecessary. If the visitor signs in, offer a one-time merge into their account with deduplication by event source and ID; the signed-in account becomes the durable identity. Allow removing saved items and clearing the anonymous plan. Browser local storage persists across sessions on the same origin but is not cross-device and may be cleared. [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage). The UK ICO treats device fingerprinting and local storage as storage/access technologies and cautions that cross-device tracking requires consent; privacy review is needed before tracking beyond the user's requested planner function. [ICO guidance](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guidance-on-the-use-of-storage-and-access-technologies/what-are-storage-and-access-technologies/)

## Search visibility: SEO and generative search

1. Make map **progressively enhanced**. Render a crawlable HTML event list and `<a href>` links server-side; an interactive map is not a substitute for readable page content. Current infinite scroll should have persistent paginated URLs and ordinary next-page links because Google generally does not click buttons or trigger infinite scrolling. [Google pagination guidance](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading), [lazy-loading guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/lazy-loading)
2. Give each Clickatick-owned event and each permitted partner detail page a stable, canonical URL, descriptive title, accurate date and location, and current status. Include only valuable, current public pages in sitemaps. Avoid mass-created city/category URLs without distinct user value; Google emphasizes original information and warns against scaled low-value pages. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [helpful content](https://developers.google.com/search/docs/fundamentals/creating-helpful-content), [AI-content guidance](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content)
3. Add `Event` JSON-LD on eligible **single-event pages**, not the all-events map. Reflect visible facts accurately. Google requires a unique leaf URL per event and accurate name/start date/location; `offers.url` must point to a crawlable page that actually offers admission. For Ticketmaster events, do not represent Clickatick as the seller or assert unverified price/availability. Validate sample URLs in the Rich Results Test and Search Console. Structured data enables eligibility but does not guarantee results. [Google Event markup](https://developers.google.com/search/docs/appearance/structured-data/event)
4. For GEO/AI search, prioritize the same sound SEO, readable content, first-party insights and utility (planner/map), honest provenance, and fast pages. Google says there is **no special AI-search schema requirement** and cautions against superficial GEO tactics. Track performance in Search Console rather than promising traffic. [Google generative AI search guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)
5. Prevent duplicate URL variants from map filters, page numbers, or preview domains. Pick canonical production URLs; do not put planner/private URLs in sitemap. Google may choose another canonical if pages are substantially duplicated from a partner. [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

## Ticketmaster rights and data gaps

**Verified:** Ticketmaster's general API terms prohibit replacing its essential experience, limit caching of Event Content to reasonable service periods, require removing content within 24 hours of owner request, require disclosure of visitor data practices, and restrict deriving revenue from the API except as otherwise permitted. The map/planner should stay a discovery aid with explicit Ticketmaster attribution and checkout on the provider. The exact effect on search indexing of syndicated Ticketmaster pages and affiliate use needs review of the owner's specific program agreement. [Ticketmaster general API terms](https://developer.ticketmaster.com/support/terms-of-use/)

**Unverified:** Ticketmaster location coverage for every event, Google Maps production credentials, affiliate approval, and any measurable SEO/GEO traffic gain. Event data, venue coordinates, availability, and image rights may vary by event. Never manufacture missing pins. Need an explicit stale/cancelled-event refresh/removal path.

## Acceptance tests for implementation

- Map and list agree for the same selected region; no-coordinate events remain discoverable in the list.
- Pan/zoom requests are debounced; map does not fetch all U.S. pages or exhaust the Ticketmaster daily quota.
- Pin links open the existing Clickatick event page; Ticketmaster checkout opens only on the user's buy action.
- Anonymous save survives reload in one browser. Signed-in merge is explicit, deduplicated, and does not expose private plans publicly.
- Non-JavaScript or crawler access reveals event links and clear headings. Partner and owned event pages have accurate canonical metadata, valid structured data where eligible, and no invented offer facts.
- Preview pages and private plans remain out of public sitemaps; production crawl behavior is checked after release.
